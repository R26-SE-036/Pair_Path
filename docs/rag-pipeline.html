PairPath · hint retrieval

How PairPath Hints Work

When a pair gets stuck, the system offers a hint — but never the answer. This explains how a hint is chosen, using a real query traced through the actual code, and why the design makes leaking a solution impossible rather than merely unlikely.

1 · What it is, and what "RAG-lite" means

RAG stands for Retrieval-Augmented Generation — the idea of looking something up in a library before answering, instead of answering from memory alone.

Most systems do the "generation" half with a language model. PairPath does not. It retrieves a passage written by a human and presents it. Nothing is invented at the moment a student asks. That is why it is called RAG-lite — the retrieval is real, the generation is deliberately absent.

This is a design decision, not a shortcut. If a machine writes the hint fresh each time, nothing can guarantee it will not hand over the answer. If the hint comes from a library that contains no answers, the guarantee holds by construction.

3 · The four parts

1

The librarian

Reads the knowledge files once when the service starts and holds them in memory, so no disk access happens while a student waits.

Each entry has three labelled parts: what it is about, the advice itself, and words to watch for in an error message.

app/rag/knowledge_loader.py
2

The search

Gives every entry a score and returns the best three. Nothing scoring zero is returned at all — a weak match is worse than none.

Three ways to earn points, weighted by how reliable each signal is:

SignalPointsWhy that weight
Question topic matches the entry+5Strongest — someone deliberately tagged this question
Keyword appears in the error+3Strong — the error is what the student is actually facing
Keyword appears in the code+1Weak — code mentions many things incidentally
app/rag/retriever.py
3

The writer

Turns the winning entry into three parts, because a single sentence is a statement while three parts is scaffolding:

  • Concept reminder — the rule they may have forgotten
  • Example idea — something concrete to try
  • Reflective question — makes them reason, rather than copy

If nothing matched, it returns a safe general hint and marks it as a fallback, rather than failing.

app/rag/hint_generator.py
4

The manager

Runs the chain and decides what kind of help is needed from the state the classifier predicted:

Predicted stateKind of hintExtra topics searched
LOGIC_STRUGGLELogic hint—
PASSIVE_NAVIGATORCollaboration promptpair programming, collaboration, role
DRIVER_DOMINANCERole balance promptpair programming, collaboration, role

Adding those extra topics matters: for a collaboration problem, the Java library is irrelevant and the collaboration guidance should win.

4 · What a knowledge entry looks like

Plain text, so anyone can add to the library without touching code:

Tags: arrays, indexing, boundaries, out of bounds
Content: Java arrays start at index 0. This means the first
  element is at array[0], and the last valid index is exactly
  array.length - 1. Attempting to access an index equal to or
  greater than array.length will cause an
  ArrayIndexOutOfBoundsException.
Keywords: array, index, outofbounds, length, bounds

Tags are matched against the question's topics. Content is what the student reads. Keywords are searched inside error text.

Notice the keywords are written without spaces — outofbounds, not "out of bounds". That is deliberate: it is exactly how the words appear inside a Java exception name like ArrayIndexOutOfBoundsException, so a real error message matches without any parsing.

Read what it does not say. It never says "change <= to <". It states the rule, suggests an inspection, and asks a question. The student still has to find their own bug — which is the entire point.

6 · Why it cannot leak the answer

The guarantee is structural, not behavioural.

No document in the library contains a solution to any exercise. The system can only return text from that library. Therefore it cannot return a solution — not because it was instructed carefully, but because there is nothing of that kind to retrieve.

A generative model would replace that guarantee with a hope. It could produce working code at any moment, and no amount of instruction reliably prevents it.

Three further properties follow from the same choice:

  • Explainable — you can point at exactly why a hint appeared, as in the score table above. Useful for a research write-up, where "the model decided" is not an answer.
  • Reproducible — the same situation always yields the same hint. Necessary if results are to mean anything.
  • Fast — a few milliseconds, no network call, no cost per hint.

What the error context is worth

The gateway now supplies all three inputs. Running the same 26 cases with and without the error and code isolates exactly what that contributes:

ExperimentRetrieval accuracyUnwanted fallbacks
A — concept tags only69.2%6 of 24
B — tags + error + code100%0 of 24

The gap is the whole argument for sending the error. Under A, a pair hitting an array error on a question tagged modulo receives generic advice; under B they receive the array-bounds concept, because the error matched. Reproduce with python dev_tools/evaluate_rag.py.

Read that 100% carefully. It is measured over 26 cases written while building the system — so it means every situation we thought of is handled, not that retrieval is perfect.

Real student errors are messier than authored ones. Adding genuine errors from real sessions to the test set is the way to turn this into a number worth defending, and it should be expected to fall when that happens.

Why not embeddings?

The usual "proper RAG" upgrade replaces keyword matching with meaning-based search. Deferred deliberately, for two reasons.

Scale. Embeddings earn their keep across thousands of documents where wording varies. Over a small, hand-curated library with deliberate tags, keyword scoring is competitive.

Explainability. The score table above would become a similarity number with no story attached. For a study that has to justify why a student received particular guidance, that is a real loss.

The plan is to evaluate embedding retrieval as a measured comparison against this baseline — not to swap it in and assume it improved. That requires being able to score the current system first.

Every number and passage on this page was produced by running the actual pipeline — the score table is a genuine trace, not an illustration.
