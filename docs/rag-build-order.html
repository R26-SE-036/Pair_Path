RAG Build Order

Your specification is sound — the pedagogical constraints in particular are the clearest in the project. The build order is what needs changing. Below: the corrected sequence, and a preview of what hints would actually look like so you can judge the design before anything is written.

Three rules that decide the order

1 · Content before search. Smarter retrieval over a thin library still returns thin answers. Nine entries cannot be rescued by better ranking.

2 · Measure before upgrade. You cannot claim semantic search improved anything without a recorded baseline. Build the ruler before rebuilding the thing you measure.

3 · Irreversible decisions last. Adding generation changes your safety claim and breaks a stated performance requirement. Make it with evidence, not in advance.

Semantic retrieval

~1 day

What the output would look like

Six representative cases, written to your §12 standard. Read them and judge whether the design holds — particularly whether any of them tells a student what to change.

Case 1 — driven by the error · ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5
Concept reminderJava arrays are zero-indexed. An array holding N elements has valid positions 0 through N−1, so the highest index you can read is one less than the length.
Example ideaTrace your loop by hand for a three-element array. Write down the index used on each pass and mark the pass where it goes past the end.
Reflective questionIf an array has N elements, what is the largest index you can safely access?
Case 2 — driven by the question · tags: modulo, conditions · wrong output, no exception
Concept reminderThe modulo operator gives the remainder left over after division. For any whole number, dividing by two leaves a remainder of either zero or one.
Example ideaWork out by hand what your condition produces for the number 4 and for the number 7, and write down the remainder in each case.
Reflective questionWhat remainder would you expect from a number that divides evenly?
Case 3 — no error, wrong behaviour · program never finishes · tags: loops
Concept reminderA loop keeps running while its condition stays true. If nothing inside the loop changes a value used in that condition, the condition can never become false.
Example ideaList every variable that appears in your loop condition, then check whether each one is updated somewhere inside the loop body.
Reflective questionWhich variable in your condition is meant to change, and where exactly does that change happen?
Case 4 — a different error family · NullPointerException at line 12
Concept reminderThis error means a variable expected to hold an object is holding nothing instead. It appears at the moment the program tries to use that variable, which may be far from where the problem began.
Example ideaLook at the line the error names and identify which variable on it might never have been given a value.
Reflective questionWhere was that variable supposed to be assigned, and is that line guaranteed to run first?
Case 5 — collaboration, not code · state: PASSIVE_NAVIGATOR · navigator only
Concept reminderThe navigator's role is to think a step ahead — watching for problems, questioning the approach, and keeping track of where the solution is going.
Example ideaAsk your partner to explain the line they just wrote before they start the next one.
Reflective questionWhat do you expect this code to do when it runs?
Case 6 — nothing matched · fallbackUsed: true
Concept reminderWhen a program does not behave as expected, the quickest route forward is usually to narrow down the first point where reality stops matching your expectation.
Example ideaPrint the values of your key variables just before and just after the section you suspect.
Reflective questionAt what point does the program's actual behaviour first differ from what you expected?

That last row is the finding worth noticing.

Every hint above meets your §12 standard, is specific to its situation, and reveals nothing — and none required generation. They are curated passages selected by retrieval.

Which suggests the honest question for stage 4 is not "how do we add an LLM" but "having seen retrieval-only output, what is generation still buying us?" That is a much better question to answer with data in hand than in advance.
