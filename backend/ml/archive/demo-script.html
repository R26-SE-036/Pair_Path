PairPath · panel demonstration

Three Minute Demo

Built for a short slot. Everything runs from the sandbox page, because live pair programming can't be made to produce a chosen state on cue — and stalling in front of a panel costs more than the realism gains. Two versions below: 60 seconds if you're squeezed, 3 minutes if you're not.

Why not a live session

A live pair takes about 3 minutes per state to register, because the model reads the last 3 minutes of behaviour. Five states is 15 minutes minimum, and even then the state you want isn't guaranteed — in testing, short sessions kept coming out as DRIVER_DOMINANCE no matter what we did.

The sandbox shows the same model, the same predictions and the same interventions — instantly and every time. That is the honest choice for a short slot, not a lesser one.

Set up before you walk in

  • All three services running — frontend 3000, API 3001, ML service 8000
  • /ml-sandbox already open, scrolled so the preset buttons and the result panel are both visible
  • Click Productive once and press Predict — proves it's alive before the panel arrives
  • Reload the page so you start clean

The 3-minute version

0:0020 sec

Frame it in one sentence

No slides. Sandbox already on screen.

"PairPath watches how two students collaborate — not whether their code is right — and classifies it into one of five states. Each state gets a different nudge. These sliders are the behaviour the model sees in a three-minute window."

0:2070 sec

Run all five states — about 14 seconds each

For each: click the preset → click Predict → point at the state and the intervention. Don't read the numbers aloud; let them see the sliders move.

productive"Working well — so it gets encouragement, not a correction."

passive navigator"The navigator has gone silent. This one goes to the navigator alone."
disengaged"Both have stopped. It nudges them to regroup."
1:3045 sec

The slider flip Do not skip

Load productive. Find Seconds since the last swap. Drag it from 200 to 600. Change nothing else. Press Predict.

It flips from Productive to Driver dominance.

"Same amount of typing, same amount of talking. The only thing that changed is how long since they swapped roles — and the verdict changes. That's the model reasoning about collaboration, not counting keystrokes."

2:1545 sec

Close with the number and the caveat

Have the results table ready — printed, or on a second screen.

"Tested on sessions the model had never seen: 89% accurate, and it beats a hand-written rule baseline by 28 points. But it's trained on generated sessions, not real students — so what we've shown is that the pipeline works end to end. Validating it with real pairs is the next phase."

Those three states carry the whole idea: one rewards, one helps, one protects a student's dignity.

If they give you an extra minute

Open the pair session in two browser windows side by side and show the passive navigator nudge arriving on one screen and not the other.

It's the strongest thing you have — visible evidence of a design decision, not just a model output. But it needs both screens visible, so only attempt it if the room allows.

Two answers to have ready

"Is this real student data?"
"No — generated sessions. We've validated the pipeline, not detection accuracy on people. That's deliberate: we'd rather report what we actually measured."

"Why is one state 100% accurate?"
"Because our generated data is cleaner than real students would be. That number is a limitation, not a result — we'd expect it to drop with real sessions."

Rehearse the slider flip until it takes ten seconds. It's the one moment that shows the model reasoning rather than reporting, and it's the part a panel will remember.
